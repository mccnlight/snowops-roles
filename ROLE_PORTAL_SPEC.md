# SnowOps Role & Portal Specification

## 1. Общая идея
- Корневая организация — **Акимат**. При первичном деплое создаётся запись `AKIMAT` и пользователь `AKIMAT_ADMIN` (суперадмин).
- Суперадмин Акимата управляет:
  - Сотрудниками акимата (`AKIMAT_USER`).
  - Единственной организацией КГУ ЖКХ (`KGU_ZKH`).
  - Организациями приёма снега (`LANDFILL`).
- Администратор КГУ создаёт сотрудников КГУ (`KGU_ZKH_USER`), подрядчиков (`CONTRACTOR`), при необходимости — операторов полигонов (`LANDFILL`) и транспорт/водителей через существующие API.
- Подрядчики (CONTRACTOR) создают своих сотрудников (`CONTRACTOR_USER`), водителей и технику.
- Операторы полигонов (LANDFILL) управляют своими пользователями и полигонами (API описаны в других сервисах).
- Все водители автоматически получают логин/пароль, чтобы входить через логин+пароль или OTP.

## 2. Роли и организации
| Организация | Админ-роль | Пользовательские роли |
|-------------|------------|-----------------------|
| AKIMAT      | `AKIMAT_ADMIN` | `AKIMAT_USER` |
| KGU_ZKH     | `KGU_ZKH_ADMIN` | `KGU_ZKH_USER` |
| LANDFILL    | `LANDFILL_ADMIN` | `LANDFILL_USER` |
| CONTRACTOR  | `CONTRACTOR_ADMIN` | `CONTRACTOR_USER`, `DRIVER` |

3. Создание организаций (`POST /roles/organizations`)
- Поля `admin_login` и `admin_password` теперь опциональны. Если не переданы:
  - Логин формируется из `name` (slug + числовой суффикс при конфликте).
  - Пароль генерируется случайно (12 символов A–Z, a–z, 0–9).
- В ответе возвращается фактический логин и сгенерированный пароль (`admin.generatedPassword`).
- Ограничение: у каждого Акимата может быть только одна организация `KGU_ZKH`. При попытке создать вторую — `409 Conflict`.

4. Управление пользователями
  4.1. Сотрудники Акимата
- `POST /roles/akimat/users` — создать `AKIMAT_USER` (только `AKIMAT_ADMIN`).
- `GET /roles/akimat/users` — список сотрудников Акимата.
  4.2. Сотрудники КГУ
- `POST /roles/kgu/users` — создать `KGU_ZKH_USER` (доступ `KGU_ZKH_ADMIN`).
- `GET /roles/kgu/users` — список `KGU_ZKH_USER`.
  4.3. Сотрудники оператора полигона
- `POST /roles/landfill/users` — создать `LANDFILL_USER` (доступ `LANDFILL_ADMIN`).
- `GET /roles/landfill/users` — список `LANDFILL_USER`.
  4.4. Водители
`POST /roles/drivers`
```json
{
  "fullName": "Иван Петров",
  "iin": "012345678901",
  "birthYear": 1995,
  "phone": "+77001234562",
  "login": "driver.ivan",   // опционально
  "password": "Secret123"   // опционально
}
```
- Доступ: `CONTRACTOR_ADMIN`.
- Если `login`/`password` пусты, сервис генерирует их автоматически и возвращает в ответе (`user.login`, `user.generatedPassword`).
- Пользователь водителя создаётся с `role=DRIVER`, `organization_id=contractor_id`, `driver_id=driver.id`.
  5. Очистка данных
- `DELETE /roles/users/:id` — удаляет пользователя, очищает его `user_sessions` и `sessions`. Параметр `?with_org=true` дополнительно удаляет его организацию вместе с дочерними организациями, водителями, транспортом. Доступен только `AKIMAT_ADMIN`.
- `DELETE /roles/organizations/:id/purge` — рекурсивно удаляет организацию и всех потомков (доступ только `AKIMAT_ADMIN`).
- БД автоматически настраивает `ON DELETE CASCADE` для `user_sessions`, чтобы FK не блокировал удаление.

  6. Фронтенд-Флоу (кратко)
 Акимат
1. Входит под `AKIMAT_ADMIN` или `AKIMAT_USER`.
2. Создаёт сотрудников (`/roles/akimat/users`).
3. Создаёт КГУ (если ещё нет) и операторов полигонов (`type = KGU_ZKH / LANDFILL`).

 КГУ ЖКХ
1. Входит под `KGU_ZKH_ADMIN` → создаёт сотрудников (`/roles/kgu/users`).
2. Создаёт подрядчиков (`type = CONTRACTOR`) и операторов полигонов.
3. Использует существующие API для тикетов/контрактов (в других сервисах).

 Подрядчик
1. `CONTRACTOR_ADMIN` создаёт сотрудников (`/roles/users`), водителей (`/roles/drivers`) и технику (`/roles/vehicles`).
2. При создании водителя фронт получает логин/пароль и отображает их менеджеру.

 LANDFILL
1. `LANDFILL_ADMIN` создаёт `LANDFILL_USER` (`/roles/landfill/users`).
2. Дальнейшие действия (полигоны, камеры) обрабатываются соответствующими сервисами.

 Водитель
- Входит по логину/паролю (или через SMS-код, если пароль сброшен).
- Токен будет содержать `role = DRIVER`; в `snowops-tickets` при отсутствии `driver_id` мы подставляем `claims.UserID`.

## 7. Требования к фронту
- Реализовать формы с новыми полями:
  - Создание организации вписывает `admin_login` и `admin_password` (поля опциональны, можно оставлять пустыми — тогда показать логин/пароль из ответа).
  - Формы создания сотрудников для Акимата, КГУ, LANDFILL.
  - Форма создания водителя — отображать выдаваемые логин/пароль.
- Учесть эндпоинты очистки (доступ в админских панелях Акимата).
- При работе с тикетами и назначениями использовать API сервиса `snowops-tickets` (уже реализованы).

Этот документ отражает все изменения, сделанные после изначального запроса, и может быть передан командам фронта и бэкенда.
