# Блокировка пользователей

## Обзор

Система поддерживает блокировку пользователей с указанием причины блокировки. Заблокированные пользователи не могут войти в систему.

## Модель данных

В модели `User` добавлено поле:
- `BlockReason *string` - причина блокировки (опционально, заполняется при блокировке)

## API

### Блокировка пользователя

**Эндпоинт:** `PUT /roles/users/:id`

**Запрос:**
```json
{
  "is_active": false,
  "block_reason": "Нарушение правил использования системы"
}
```

**Поведение:**
- При установке `is_active: false` можно указать причину блокировки в поле `block_reason`
- Если `block_reason` не указан, поле останется `null`
- При установке `is_active: true` (разблокировка) поле `block_reason` автоматически очищается (`null`)

**Примеры:**

1. Блокировка с причиной:
```json
{
  "is_active": false,
  "block_reason": "Нарушение правил использования системы"
}
```

2. Блокировка без причины:
```json
{
  "is_active": false
}
```

3. Разблокировка:
```json
{
  "is_active": true
}
```
(При этом `block_reason` автоматически очистится)

4. Обновление только причины (если пользователь уже заблокирован):
```json
{
  "block_reason": "Новая причина блокировки"
}
```

### Просмотр пользователя

**Эндпоинт:** `GET /roles/users/:id`

**Поведение:**
- **Администраторы** (`AKIMAT_ADMIN`, `KGU_ZKH_ADMIN`, `LANDFILL_ADMIN`, `CONTRACTOR_ADMIN`) могут видеть заблокированных пользователей
- **Обычные пользователи** видят только активных пользователей (`is_active = true`)

**Ответ:**
```json
{
  "user": {
    "id": "...",
    "phone": "+77001234567",
    "role": "CONTRACTOR_USER",
    "is_active": false,
    "block_reason": "Нарушение правил использования системы",
    ...
  }
}
```

## Автоматическая блокировка

### При деактивации организации

При деактивации организации (`DELETE /roles/organizations/:id`) все пользователи организации автоматически блокируются с причиной:

```
"Организация '{название организации}' была деактивирована"
```

### При деактивации организации подрядчика

При деактивации организации подрядчика также блокируются все пользователи водителей с причиной:

```
"Организация подрядчика '{название организации}' была деактивирована"
```

## Права доступа

- Блокировать пользователей могут администраторы соответствующих уровней:
  - `AKIMAT_ADMIN` - может блокировать всех пользователей
  - `KGU_ZKH_ADMIN` - может блокировать пользователей КГУ и подчинённых организаций
  - `CONTRACTOR_ADMIN` - может блокировать пользователей своей организации
  - `LANDFILL_ADMIN` - может блокировать пользователей своей организации

## Миграция базы данных

Поле `block_reason` добавляется автоматически при запуске приложения через GORM AutoMigrate.

Если нужно добавить поле вручную:
```sql
ALTER TABLE users ADD COLUMN block_reason TEXT;
```

## Проверка блокировки в других сервисах

Другие сервисы (например, `snowops-auth-service`) должны проверять поле `is_active` при аутентификации пользователя и отклонять запросы от заблокированных пользователей.
