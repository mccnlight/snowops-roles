# Управление организациями и пользователями

## Роли
- `AKIMAT_ADMIN` – главный администратор акимата (сидируется автоматически). Может создавать сотрудников Акимата, КГУ и организации LANDFILL.
- `AKIMAT_USER` – сотрудник Акимата (`POST /roles/akimat/users`).
- `KGU_ZKH_ADMIN` – администратор КГУ (создаётся вместе с организацией `KGU_ZKH`).
- `KGU_ZKH_USER` – сотрудник КГУ (`POST /roles/kgu/users`).
- `LANDFILL_ADMIN` – администратор оператора полигона (создаётся при создании организации `LANDFILL` или старого типа `TOO`).
- `LANDFILL_USER` – сотрудник оператора полигона (`POST /roles/landfill/users`).
- `CONTRACTOR_ADMIN` – администратор подрядчика (создаётся при создании `CONTRACTOR`).
- `CONTRACTOR_USER` – сотрудник подрядчика (`POST /roles/users`).
- `DRIVER` – водитель (создаётся автоматически при `POST /roles/drivers`).

## Создание организаций
`POST /roles/organizations`
```json
{
  "name": "TOO Snow Demo",
  "type": "CONTRACTOR", // или "KGU_ZKH", "LANDFILL" (принимается также старое значение "TOO")
  "bin": "123456789012",
  "head_full_name": "Иван Иванов",
  "address": "Астана",
  "phone": "+77001234567",
  "admin_full_name": "Администратор",
  "admin_phone": "+77001234568",
  "admin_login": "snow.demo",        // опционально; если не передать, сгенерируем из name
  "admin_password": "Secret123!"     // опционально; если не передать, сгенерируется автоматически
}
```

### Что происходит автоматически
- Если `admin_login`/`admin_password` не переданы, логин формируется из `name`, пароль генерируется случайно (12 символов A-Za-z0-9).
- Логин проверяется на уникальность, при конфликте добавляется числовой суффикс.
- В ответе возвращаются логин и фактический пароль (либо переданный, либо сгенерированный):
```json
{
  "organization": { ... },
  "admin": {
    "id": "...",
    "login": "too_snow_demo",
    "generatedPassword": "X1yZ..."
  }
}
```
- Для акимата разрешено создать только одну КГУ. При попытке создать вторую — `409 Conflict`.

## Сотрудники акимата
### Создать сотрудника
`POST /roles/akimat/users`
```json
{
  "phone": "+77001234560",
  "login": "akimat.user1",
  "password": "Secret123"
}
```
- Доступ: только `AKIMAT_ADMIN`.
- Пользователь создаётся с ролью `AKIMAT_USER` и привязан к организации акимата.

### Список сотрудников
`GET /roles/akimat/users`
- Доступ: `AKIMAT_ADMIN`.
- Возвращает всех пользователей с ролью `AKIMAT_USER` текущего акимата.

## Сотрудники КГУ
### Создать сотрудника
`POST /roles/kgu/users`
```json
{
  "phone": "+77001234561",
  "login": "kgu.manager1",
  "password": "Secret123"
}
```
- Доступ: только `KGU_ZKH_ADMIN`.
- Пользователь получает роль `KGU_ZKH_USER` и привязывается к текущему КГУ.

### Список сотрудников
`GET /roles/kgu/users`
- Доступ: `KGU_ZKH_ADMIN`.
- Возвращает всех `KGU_ZKH_USER` текущего КГУ.

```json
{
  "phone": "+77001234562",
  "login": "landfill.user1",
  "password": "Secret123"
}
```

## Водители
### Создать водителя
`POST /roles/drivers`
```json
{
  "fullName": "Иван Петров",
  "iin": "012345678901",
  "birthYear": 1995,
  "phone": "+77001234562",
  "login": "driver.ivan",       // опционально
  "password": "Secret123!"      // опционально
}
```
- Доступ: только `CONTRACTOR_ADMIN`.
- Если `login`/`password` не переданы, система генерирует логин (slug по ФИО) и пароль (12 символов A-Za-z0-9).
- В ответе возвращается пользователь с полями `login` и `generatedPassword`, чтобы подрядчик мог передать их водителю.

### Ответ (фрагмент)
```json
{
  "driver": { ... },
  "user": {
    "id": "uuid",
    "login": "driver_ivan",
    "generatedPassword": "Abc123Xyz890",
    ...
  }
}
```

## Очистка тестовых данных
- `DELETE /roles/users/:id` — удаляет пользователя. Опционально добавьте `?with_org=true`, чтобы вместе с пользователем удалить его организацию и всё дерево дочерних организаций. Доступно только `AKIMAT_ADMIN`.
- `DELETE /roles/organizations/:id/purge` — рекурсивно удаляет организацию, все дочерние записи, пользователей, водителей, технику. Доступно только `AKIMAT_ADMIN`.

## Остальные сущности
- Подрядчики (`type = CONTRACTOR`) и операторы полигонов (`type = LANDFILL` или `TOO`) создаются через `/roles/organizations`, вместе с ними появляется администратор.
- Сотрудники подрядчика и водители создаются существующими эндпоинтами (`/roles/users`, `/roles/drivers`).
- Транспорт (`/roles/vehicles`) привязывается к организации подрядчика.

## Системные ограничения
- Телефон и логин должны быть уникальны. При конфликте возвращается `409 Conflict`.
- Все новые эндпоинты работают только при наличии действующего JWT токена и роли, указанной выше.
